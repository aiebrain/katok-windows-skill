# 창 선택과 입력 검증

현재 Computer Use 문서의 관찰 → 별도 호출에서 입력 한 번과 즉시 재관찰 절차를 따른다. 이 문서는 절차이며 자동 전송 스크립트가 아니다.

## 창 선택

- 알려진 실행 중 앱은 `sky.list_windows()`로 찾고 사용자 지정 방 후보만 출력한다. 실제 반환된 `app`·`id`를 사용한다.
- 지정 방이 이미 열려 있으면 그 창을 바로 읽는다. 방이 없을 때만 `list_apps()`와 메인 창을 통해 사용자 요청의 대상을 찾는다.
- 정확히 하나의 대상 창이 정해지기 전에는 입력하지 않는다. 이미지의 제목은 현재 창과 시각적으로 대조한다. 동명 방·모호한 계정은 먼저 확인한다.
- `get_window_state`의 스크린샷과 필요한 접근성 정보를 확인한다. 제목만으로 현재 계정·참여자가 확인됐다고 주장하지 않는다.
- 카카오톡 접근성 트리에는 광고만 상세하게 나올 수 있다. 광고 요소를 채팅 검색·입력창으로 착각하지 않는다.
- 스크린샷은 도구가 자동 표시한다. 다시 디코딩하거나 파일에 저장하지 않는다.

## 한 번의 입력

관찰 호출에서 방과 입력창을 확인하고 멈춘다. 실제 입력창을 클릭한 후 새 상태에서 포커스를 확인한다. 창 제목이나 프로세스만으로 입력 포커스를 판단하지 않는다. 이미 있는 초안은 임의로 지우거나 덮어쓰지 않는다.

다음 호출에서는 입력 한 번과 즉시 재관찰만 수행한다. 좌표 클릭에는 직전 관찰의 `screenshotId`와 창 상대 좌표를 사용한다. 입력 뒤에는 이전 좌표·요소 번호를 사용하지 않는다.

`type_text`에는 문자만 전달하고 Enter·Tab 등의 동작과 구분한다. 여러 줄 입력이나 Enter 전송 설정을 추측하지 않는다. 안전한 줄바꿈 방법이 확인되지 않으면 앱 입력 전에 멈추고 본문을 사용자에게 전달한다.

입력과 직후 화면 읽기의 오류를 별도로 구분한다. 다음은 두 번째 호출 내부의 의사코드이며, 호출 간 관찰 단계는 생략하지 않는다.

```text
기준 = 직전 호출에서 관찰한 방·입력창·마지막 말풍선
postState = 없음; actionError = 없음; observationError = 없음
actionPhase = started
try:
    승인 범위의 UI 입력을 정확히 한 번 실행
    actionPhase = returned
catch:
    actionPhase = threw
    actionError = 개인 내용을 제외한 짧은 오류 종류
try:
    postState = 같은 창의 get_window_state로 즉시 새 상태 읽기
catch:
    observationError = 개인 내용을 제외한 짧은 오류 종류
actionPhase, actionError, observationError, postStateAvailable만 간단히 알림
현재 호출 종료 — 추가 입력 없음
```

`threw`도 실제 입력이 반영됐을 수 있다. `returned`도 전송 성공을 증명하지 않는다. 단계 표시나 새 상태가 없거나 도구 출력 전체가 끊겼으면 효과는 미확인이다. 오래된 `postState`를 성공 증거로 재사용하지 않는다. 오류 본문·전체 스택·개인 내용을 파일에 기록하지 않는다.

새 상태를 얻었으면 다음 호출에서 아래 복구 표를 해석한다. 새 상태가 없으면 이후 한 번의 읽기 전용 창 재연결로 확인한다. 모달이 보이지 않으면 실제 `list_windows()` 결과로 다시 선택한다. 로그인·잠금·권한 화면은 사용자가 처리한다.

## 전송

1. 방과 최종 텍스트를 확정한다. 입력·전송 직전 상태를 읽고 방, 입력창 내용, 마지막 말풍선 위치를 비교 기준으로 삼는다. 개인 내용이 포함된 기준은 현재 작업 메모리에만 두며 파일로 저장하지 않는다.
2. 사용자가 지정한 방·최종 텍스트·지금 전송한다는 지시가 동일한 실행의 유효한 승인이면 다시 묻지 않는다. 일반적인 설치 허가나 “알아서 보내”를 구체적인 실행 승인으로 취급하지 않는다. 민감 정보는 입력부터 적용되는 확인 정책을 따른다.
3. 입력창에 승인된 텍스트를 입력하고 새 화면에서 전체 내용과 포커스를 확인한다. 초안만 요청했다면 여기서 멈춘다.
4. 적용되는 실행 시점 확인이 충족됐고 방·초안·행동이 그대로인지 확인한다. 대상이나 내용이 바뀌면 전송하지 말고 달라진 부분의 승인을 받는다.
5. 전송 호출을 시작하기 직전에 메모리의 `sendAttemptStarted = true`로 표시하고, 방금 관찰한 전송 버튼을 한 번 누른 뒤 즉시 새 상태를 읽는다. Enter는 해당 입력창에서 전송 동작임이 확인된 경우에만 사용한다. 반환·오류·출력 중단 여부와 관계없이 이 실행의 전송 시도 표시는 되돌리지 않는다.
6. 직전 기준보다 뒤에 정확한 최종 텍스트의 새 발신 말풍선이 나타났고 입력창이 비었는지 확인한다. 과거의 동일 문구, 빈 입력창, 도구 반환 성공 하나만으로 전송 완료를 주장하지 않는다. 확인된 전송과 상대방 읽음은 구분한다.

파일·이미지 전송은 이 절차의 범위 밖이다. 별도 요청과 실제 첨부 UI·업로드 정책 검토가 필요하다.

## 오류 복구

오류 반환은 미실행의 증거가 아니다. 입력과 관찰 각각의 결과가 없거나 도구 호출 전체가 끊겼으면 효과는 미확인으로 둔다. 새 화면을 읽기 전에는 입력을 반복하지 않는다.

| 오류 후 현재 관찰 | 처리 |
|---|---|
| 텍스트 입력 단계 오류 뒤, 같은 방의 입력창에 승인 텍스트가 정확히 전부 있음 | 재입력하지 않고 원래 요청의 초안 완료 또는 최초 전송 확인 단계로 이동 |
| 텍스트 입력 단계 오류 뒤, 입력창이 비었거나 일부만 입력됨 | 자동 재입력하지 않고 현재 상태 그대로 멈춤 |
| 텍스트 입력 단계 오류 뒤, 입력창에 다른 내용이 있음 | 삭제·덮어쓰기 없이 멈춤 |
| 방이 달라졌거나 대상·포커스·전체 텍스트를 확인할 수 없음 | 어느 방에도 추가 입력·전송하지 않고 대상부터 재확인. 다른 방에 입력됐을 수 있는 내용도 자동 삭제·수정하지 않음 |
| 전송 오류 뒤 같은 방에 기준 이후의 새 발신 말풍선과 빈 입력창이 확인됨 | 전송 확인으로 보고, 다시 보내지 않음 |
| 같은 문구의 예전 말풍선만 있거나 새 메시지인지 구분되지 않음 | 전송 여부 미확인, 재전송하지 않음 |
| 화면·접근성 정보 충돌 또는 전송 후 입력 내용이 남아 있음 | 전송 여부 미확인, 재전송하지 않음 |

창 재연결이 필요하면 `list_windows()`로 실제 대상 창을 다시 찾고 `get_window()` 후 한 번 읽는다. 이 복구는 읽기만 수행한다. 같은 방임을 다시 확인한 뒤에만 위 표를 적용한다. 복구에도 실패하면 이전 좌표·핸들로 입력하지 말고 중단한다. 잠긴 화면이나 사용자 중단 신호는 즉시 멈춘다.

`sendAttemptStarted`가 설정됐거나 전송 호출이 시작됐을 가능성을 배제할 수 없으면 입력 단계의 복구 규칙으로 돌아가지 않는다. 오류 단계가 미확인이거나 입력창에 승인 문구가 남아 있어도 두 번째 전송을 허용하지 않는다.

## 확인된 실행 경험

2026-09-09 Windows 카카오톡에서 앱·창 선택, 화면 읽기, 사용자 지정 단일 텍스트 입력과 한 번의 전송, 새 발신 말풍선 확인까지 성공했다.

텍스트 입력과 이어진 화면 읽기를 수행한 호출에서 `window is not a usable app window`가 반환됐지만, 창 재연결 후 승인 텍스트가 이미 전부 입력돼 있음을 확인했다. 어느 단계에서 오류가 발생했는지와 내부 원인은 확인되지 않았다. 따라서 이를 입력 실패나 원인 해결의 증거로 삼지 않는다. 재입력하지 않고 한 번 전송하여 중복을 피했다.

이 성공 이력은 현재 세션의 창·권한·포커스 확인을 대신하지 않는다. 여러 줄·파일·이미지 전송은 검증하지 않았다.
